# Telegram Manager — MVP Plan

> Статус: рабочее техническое задание (v0.1)  
> Дата: 2026-11-22  
> Цель: локальное приложение с веб-панелью для авторизации Telegram-аккаунта, выбора группы, получения **доступного через Telegram API** списка участников и экспорта результатов.

## 1. Цель продукта

Пользователь запускает приложение одной командой. Локальный сервер стартует, браузер открывает веб-панель. Пользователь подключает собственный Telegram-аккаунт, выбирает доступную группу-источник, запускает сбор видимых участников и просматривает/экспортирует результат.

**Главный результат MVP:** полный сквозной сценарий `запуск → авторизация → выбор группы → сбор → просмотр → CSV` без командной строки после старта.

### 1.1 Входит в MVP

- Локальный запуск из `python launcher.py` с автоматическим открытием браузера.
- Web UI: статус подключения, авторизация, список групп, запуск и история сборов, таблица участников, экспорт CSV.
- Авторизация пользовательского аккаунта через Telethon: `api_id`, `api_hash`, телефон, одноразовый код, пароль 2FA (если включён), восстановление локальной сессии.
- Выбор группы из доступных диалогов и поиск по публичному `@username`/ссылке, **без автоматического вступления**.
- Сбор только тех участников, которых Telegram API действительно возвращает текущему аккаунту.
- Сохранение данных в SQLite с дедупликацией и связью участника с источником.
- Фоновая асинхронная задача сбора с прогрессом, отменой, статусом и диагностикой ошибок.
- CSV-экспорт результата конкретного сбора в UTF-8 с BOM для Excel.
- Настраиваемый безопасный локальный адрес, базовые логи без секретов, понятные сообщения о лимитах и недостаточном доступе.

### 1.2 Не входит в MVP

- Автоматическое добавление чужих участников в контакты или в группу; массовые сообщения и инвайты.
- Обход скрытых списков участников, ограничений доступа/приватности или антиспам-защиты.
- Поддержка нескольких аккаунтов, массовое сканирование множества групп, прокси-пулы, планировщик по расписанию.
- Удалённый/публичный веб-сервис, развёртывание на VPS, Docker и многопользовательский доступ.
- Формирование EXE, биллинг, облачная синхронизация.
- Получение номеров телефонов: Telethon не гарантирует их видимость, и MVP не пытается их извлекать.

> **После MVP:** выбор целевой группы, работа с приглашениями по согласию, улучшенная аналитика, упаковка для Windows. Эти функции проектируются как расширения, но не блокируют MVP.

## 2. Стек и архитектурные решения

| Слой | Технология | Решение |
|---|---|---|
| Telegram API | Python + Telethon | Один долгоживущий клиент, принадлежащий приложению |
| HTTP API | FastAPI + Pydantic | REST для действий и чтения |
| Real-time | WebSocket | Статусы фоновых задач, без опроса каждую секунду |
| Backend runtime | Uvicorn + asyncio | Один процесс, один основной event loop |
| UI | React + TypeScript + Vite | Собирается в статические файлы для локального запуска |
| Хранилище | SQLite + SQLAlchemy 2.x + Alembic | Миграции с первого этапа |
| Тесты | pytest + httpx + Vitest | Telegram интеграции мокировать в CI |
| Логи | `logging` | Без кодов авторизации, `api_hash`, сессионных строк и персональных данных в сообщениях |

### 2.1 Схема взаимодействия

```text
launcher.py
   └── FastAPI / Uvicorn (localhost:8000)
          ├── /api/*  ───────────┐
          ├── /ws/tasks         │
          ├── React static      │
          └── Services          │
                 ├── TelegramSessionManager → Telethon → Telegram
                 ├── GroupService
                 ├── ParseTaskManager → ParticipantCollector
                 └── Repository → SQLite

Browser (React) → REST / WebSocket
```

**Инварианты:** Telethon запускается на том же event loop, что и менеджер задач; API не создаёт `TelegramClient` на каждый запрос; записи в SQLite выполняются транзакционно; пользовательское UI не выполняет Telegram-операции напрямую.

## 3. Пользовательские сценарии

### UC-01. Первый запуск
1. Установлены Python 3.12+ и необходимые зависимости; frontend предварительно собран (в dev-режиме запускается Vite отдельно).
2. Пользователь выполняет `python launcher.py`.
3. Backend слушает `127.0.0.1:8000` (не `0.0.0.0`).
4. После проверки `/api/health` автоматически открывается `http://127.0.0.1:8000`.
5. Если сессии нет, панель показывает форму Telegram-входа.

**Готово, если:** можно попасть в интерфейс, перезапустить приложение и не потерять данные.

### UC-02. Telegram-вход
1. Ввести `api_id`, `api_hash` (получить у Telegram через `my.telegram.org`), номер телефона.
2. Запросить код, ввести его в форме.
3. Если Telegram требует 2FA, показать отдельный шаг пароля.
4. После успешного входа показать имя/username и статус `connected`.
5. Сохранить сессию в локальной директории `data/sessions` с ограниченными правами доступа; секреты не отдавать обратно в API/UI.

**Ошибки:** неверный код, истёкший код, неправильный пароль, превышен лимит запросов, сеть недоступна, потерянная сессия. UI должен дать понятное действие для восстановления.

### UC-03. Выбор источника
1. После входа загрузить список доступных диалогов.
2. Отобразить название, тип, ID и публичный username (если есть).
3. Дать поиск по списку и поле для публичной ссылки или `@username`.
4. При выборе проверить доступ к объекту и показать предупреждение, если участники не видны.

**Ограничение:** закрытые группы доступны только при имеющихся правах/членстве. Не вступать автоматически, не обещать полный список даже для открытой группы.

### UC-04. Сбор участников
1. Выбрать группу и нажать «Собрать участников».
2. Создать задачу с уникальным ID, `source_group_id`, временем старта.
3. В фоне пройти доступных участников через Telethon, не блокируя запросы к API.
4. Сохранять пользователей и связи с группой **пакетами**; не создавать дубликаты по Telegram ID.
5. Передавать прогресс: `processed`, `saved`, `skipped`, `failed`, `status`.
6. Позволить отменить задачу; результат уже сохранённых записей остаётся доступным.
7. При `FloodWaitError` показать время ожидания и перейти в статус `waiting` либо завершить с понятной ошибкой. Не пытаться обходить ограничения.

**Важно:** прогресс может иметь неизвестный знаменатель. Не отображать выдуманный процент, если Telegram не предоставил достоверное общее число. `completed` означает «доступная выборка исчерпана», а не «получены все члены группы».

### UC-05. Результаты и экспорт
1. Открыть завершённый/отменённый сбор.
2. Просмотреть таблицу с серверной пагинацией и поиском по имени/username.
3. Экспортировать записи **конкретной задачи** в CSV.
4. Использовать столбцы: `telegram_id`, `username`, `first_name`, `last_name`, `is_bot`, `source_group_id`, `collected_at`.
5. Корректно экранировать CSV, предотвращать CSV formula injection при открытии в табличных редакторах.

## 4. Страницы веб-панели

| Маршрут UI | Содержание |
|---|---|
| `/` | Dashboard: состояние аккаунта, последний сбор, быстрый запуск |
| `/auth` | Пошаговый Telegram-вход, 2FA, ошибки, выход |
| `/groups` | Диалоги/группы, поиск, проверка доступа, выбор источника |
| `/tasks` | История сборов, текущий статус, отмена |
| `/tasks/:id` | Прогресс, ошибки, результаты, экспорт |
| `/settings` | Информация о приложении, путь к данным, безопасное отключение аккаунта |

UI-состояния, которые необходимо нарисовать явно: `loading`, `empty`, `not_authenticated`, `running`, `waiting`, `completed`, `cancelled`, `failed`, `no_access`.

## 5. Модель данных

### `accounts`
- `id` — PK (внутренний)
- `telegram_user_id` — unique, nullable до авторизации
- `display_name`, `username` — nullable
- `session_path` — путь к локальной сессии, не содержимое сессии
- `created_at`, `updated_at`

### `groups`
- `id` — PK (внутренний)
- `account_id` — FK → `accounts.id`
- `telegram_group_id` — unique для одного аккаунта
- `title`, `username`, `group_type`, `access_state`
- `last_checked_at`

### `users`
- `telegram_user_id` — PK
- `username`, `first_name`, `last_name`, `is_bot`
- `updated_at`

### `parse_tasks`
- `id` — UUID PK
- `source_group_id` — FK → `groups.id`
- `status` — `pending | running | waiting | completed | cancelled | failed`
- `processed_count`, `saved_count`, `skipped_count`, `error_count`
- `started_at`, `finished_at`, `created_at`
- `error_code`, `error_message` — без секретов

### `task_members`
- `task_id` — FK → `parse_tasks.id`
- `telegram_user_id` — FK → `users.telegram_user_id`
- `collected_at`
- composite PK (`task_id`, `telegram_user_id`)

### `group_members`
- `group_id` — FK → `groups.id`
- `telegram_user_id` — FK → `users.telegram_user_id`
- `first_seen_at`, `last_seen_at`
- composite PK (`group_id`, `telegram_user_id`)

**Индексы:** `parse_tasks(status, created_at)`, `task_members(task_id)`, `users(username)`; включить foreign keys для SQLite. Важно различать глобальную карточку пользователя, членство в группе и принадлежность к конкретному сбору.

## 6. Контракт REST API (v1)

### Система и авторизация
- `GET /api/health` → `{ "status": "ok" }`
- `GET /api/auth/status` → `{ "authenticated": boolean, "account": {...} | null }`
- `POST /api/auth/start` → `{ "api_id": number, "api_hash": string, "phone": string }`, ответ `{ "challenge_id": string, "next_step": "code" }`
- `POST /api/auth/verify-code` → `{ "challenge_id": string, "code": string }`, ответ с `next_step: "complete" | "password"`
- `POST /api/auth/verify-password` → `{ "challenge_id": string, "password": string }`
- `POST /api/auth/logout` → завершить локальную сессию; удаление сохранённой сессии — отдельное явное действие

### Группы
- `GET /api/groups?search=&page=&page_size=` → пагинированный список доступных групп
- `POST /api/groups/resolve` → `{ "link_or_username": string }`, разрешить адрес при наличии доступа
- `GET /api/groups/{id}/access` → `{ "can_read_members": boolean | null, "reason": string | null }`

### Задачи и участники
- `POST /api/tasks/parse` → `{ "source_group_id": number }`, ответ `202 Accepted` с `{ "task_id": "..." }`
- `GET /api/tasks?page=&page_size=` → история задач
- `GET /api/tasks/{id}` → статус/счётчики/ошибки
- `POST /api/tasks/{id}/cancel` → запрос отмены
- `GET /api/tasks/{id}/members?search=&page=&page_size=` → серверная пагинация
- `GET /api/tasks/{id}/export.csv` → CSV-файл
- `WS /ws/tasks` → события `{ "task_id", "status", "processed", "saved", "skipped", "errors", "message" }`

**Общие правила API:** единый формат ошибок `{ "code": "...", "message": "..." }`; валидация входных данных; `401` при отсутствии авторизации Telegram, `404` при неизвестной сущности, `409` при конфликте состояния, `429` при ограничениях (если применимо), `500` только для неожиданных ошибок. Для локального API предусмотреть защиту от посторонних сайтов: проверять `Origin` для изменяющих запросов и WebSocket, запретить wildcard CORS; не полагаться только на `127.0.0.1`.

## 7. Менеджер задач и ограничения

- В MVP **одна активная задача сбора** на аккаунт; новые запросы при занятом слоте получают `409`.
- Состояние задачи хранится в БД, а не только в памяти.
- WebSocket отправляет события, но UI всегда может восстановиться из `GET /api/tasks/{id}`.
- По завершении процесса задача `running/waiting` из прошлого запуска помечается как `failed` с причиной `interrupted`; автопродолжение — позже.
- Отмена кооперативная: установить флаг, закончить текущий запрос/транзакцию, сохранить статус `cancelled`.
- Обрабатывать RPC-ошибки Telethon, ошибки сети, неизвестную группу и отсутствие доступа.
- Ограничения Telegram соблюдать; не вводить искусственную «скорость обхода» или механизмы уклонения от ограничений.

## 10. Definition of Done — MVP

- [ ] Чистая установка и запуск по README воспроизводимы.
- [ ] Панель открывается автоматически при запуске Python.
- [ ] Можно войти в Telegram, включая 2FA, и восстановить сессию.
- [ ] Можно выбрать доступную группу без ручного ввода ID.
- [ ] Сбор не зависает в HTTP-запросе, статус виден в панели.
- [ ] Список пользователей сохраняется, повторные сборы не плодят дубликаты.
- [ ] Недоступный/скрытый список обрабатывается честно, без ложного статуса «собрано всё».
- [ ] Есть отмена, понятные ошибки и корректная обработка FloodWait.
- [ ] Есть таблица участников и CSV-экспорт конкретного сбора.
- [ ] Данные переживают рестарт, незавершённые задачи помечаются корректно.
- [ ] API слушает только localhost, изменяющие запросы защищены от нежелательного origin.
- [ ] Нет секретов/сессий в git, логах и клиентских ответах.
- [ ] Backend-тесты и frontend-тесты проходят.

## 11. Технические риски и решения

| Риск | Решение |
|---|---|
| Telegram показывает неполный/скрытый список | Не обещать полноту; показать доступный объём и состояние доступа |
| FloodWait / ограничения API | Ожидать предписанное время или завершить с явной причиной; не обходить лимиты |
| Сессия украдена из файлов | Хранить локально, ограничить права на каталог, никогда не коммитить; предусмотреть отключение |
| Конфликты Telethon и FastAPI event loop | Один долгоживущий клиент в lifespan FastAPI и асинхронные сервисы |
| Сбой приложения в середине сбора | Пакетные commit, сохранённый прогресс, статус `interrupted` после рестарта |
| Большая группа и рост памяти | Потоковая обработка, батчи, серверная пагинация |
| React dev server не работает в production | Собирать `frontend/dist` и раздавать его через FastAPI |
| CSV с формулами в имени | Экранировать значения, которые Excel трактует как формулы |

## 12. Правила разработки

1. Реализовывать **один этап M0–M6 за один PR/логический коммит**.
2. Перед изменениями читать этот файл и текущий README.
3. Не добавлять функции вне MVP без согласованного изменения плана.
4. Покрывать тестами публичное API и критическую логику задач.
5. Не встраивать настоящие `api_id`, `api_hash`, OTP, пароли, session-файлы в код/фикстуры.
6. После каждого этапа фиксировать: **что изменено, как запустить, какие тесты прошли, какие ограничения остались**.
7. Не создавать обходы приватности или антиспам-ограничений Telegram.

## 13. Открытые решения (не блокируют M0)

- Поддерживать только Windows на первом релизе или также Linux? Рекомендуется писать кроссплатформенно, проверить обе ОС.
- В MVP один Telegram-аккаунт; при переходе к нескольким придётся учитывать составные ключи для групп и собственные сессии.
- Вид таблицы: минимальный интерфейс без UI-фреймворка или готовый набор компонентов; можно выбрать на M0.
- Нужно ли хранить историю всех сборов бессрочно? Пока да, очистку данных добавить после MVP.
